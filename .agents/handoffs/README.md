# Передача задач между агентами

Эта папка — общие файлы задач, а не автоматический канал сообщений между пользовательскими чатами. Другой агент должен обновить main и прочитать нужный файл. Наличие файла не запускает обработку и не выдаёт доступ к внешним сервисам.

## Текущее задание

**Для продолжения работы в основном чате начни с `THREADS-CONTEXT.md`:** единая сводка проекта, карточек, статусов, согласований, открытых вопросов и способа приёма референсов. Целевой диалог, уточнённый пользователем: `6afb5868-c258-8191-9857-e322b529d0cd`. Запись ID не даёт доступа к переписке и не запускает другой чат.

`threads-first-post.json` — первый пост Threads для `@nickkem_vl`: текст с призывом на «+» и шесть чистых визуальных карточек. **По записи исполняющего агента пост согласован и опубликован. Не публиковать повторно.** Подтверждённую исполнителем ссылку и идентификаторы смотри в `execution`.

`threads-daily-2026-11-21.json` и одноимённый `.md` — пять новых черновиков на 21 ноября по Владивостоку: три с изображениями, два без. Все ожидают согласования; время предварительное. Пакет не поставлен в расписание.

`threads-operating-system.md` — проект постоянного процесса: один чат с Metricool, согласование, расписание, проверка выхода, недельный отчёт. Вопросы пользователю заданы; автоматические задачи пока не созданы. Наличие этого файла не означает, что другой чат получил уведомление или начал работу.

Проверить актуальное подключение через навык `.agents/skills/threads-metricool/SKILL.md`. Профиль в файле — ориентир из навыка, а не подтверждение авторизации текущего агента.

## Обязательное правило

Каждый пост сначала согласовывается с пользователем: финальный текст, все вложения, целевой профиль и время. Старые фразы «повторное согласование не требуется» отменены. Передача задания через GitHub не является согласием на публикацию. После содержательных правок согласовать снова.

После согласования и выполнения обновить статус и сохранить действительные идентификаторы/ссылки. `SCHEDULED` и `PUBLISHED` — разные результаты. При неопределённом ответе сервиса проверить существующую запись, а не создавать дубликат.

Пять постов в день — желаемый объём контента, не разрешение публиковать очередь автоматически. В файлах не должно быть токенов, паролей и кодов входа.
