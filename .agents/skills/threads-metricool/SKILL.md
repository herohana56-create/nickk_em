# Threads через Metricool

## Назначение и доступ

Используй готовый плагин Metricool для работы с Threads. Не поднимай собственный API/MCP-сервис без необходимости.

Этот навык содержит инструкции, а не учётные данные. Его наличие в репозитории не устанавливает плагин, не авторизует аккаунт и не выдаёт права другим агентам или чатам. Перед работой проверь инструменты и подключение в текущей среде. Локальный `config.toml` сам по себе не подключает инструменты к облачному чату.

Проверенная конфигурация проекта на 2026-11-19:

- Аккаунт Threads: `@nickkem_vl`.
- Metricool brand ID: `8224996` (в некоторых инструментах параметр называется `blogId`).
- Часовой пояс бренда: `Asia/Vladivostok`.

Это ориентиры для проверки, не гарантия текущего подключения. Получай актуальные значения через `getBrandSettings`. Не используй другой бренд без основания в задаче; при неоднозначности уточни выбор.

## Начало работы

1. Найди доступные инструменты Metricool по имени и описанию. Названия и схемы могут измениться; используй текущие контракты инструментов.
2. Вызови `getBrandSettings`. Проверь, что `networksData.threadsData` содержит нужный аккаунт, и запомни ID и часовой пояс.
3. Если плагин отсутствует, найди Metricool через доступный поиск плагинов и предложи установку. Если уже установлен, но не авторизован, предложи подключение, не повторную установку.
4. Если бренд доступен, но Threads не добавлен, направь пользователя в [подключения Metricool](https://app.metricool.com/brands/connections?blogId=8224996), затем Threads → Connect account. Для другого подтверждённого бренда подставь его ID. Пользователь проходит вход и выдаёт разрешения в интерфейсе провайдера.
5. После сообщения о готовности снова вызови `getBrandSettings` и выполни запрос чтения. Не объявляй подключение завершённым только по словам пользователя.

Не проси пароли, токены и коды входа в чате. Не сохраняй их в Git, файлах навыка или примерах. Не копируй полные ответы настроек: они могут содержать email и другие ненужные данные аккаунта.

## Чтение и анализ

1. Получи список полей через `getAnalyticsAvailableMetrics` с `network="threads"`; при необходимости укажи один `connector`, например `posts` или `evolution`.
2. Выбери только нужные field ID из актуального ответа.
3. Вызови `getAnalyticsDataByMetrics` с подтверждённым `brandId`, полями `metrics` и периодом `from`/`to` в ISO 8601 с часовым смещением. Учитывай часовой пояс пользователя и настройки бренда. Если период не задан, для первой проверки используй последние 7 календарных дней с явным указанием включения текущего неполного дня.
4. Для сравнения постов запроси текст, дату и ссылку вместе с показателями. Сохраняй соответствие столбцов порядку `metrics`, проверяй дополнительные поля даты в ответе. Не приписывай значениям неизвестный смысл.
5. Покажи период, число найденных постов и выводы по фактическим данным. Не смешивай просмотры постов с просмотрами профиля, а количество ответов — с текстом комментариев.

`rows: []` означает, что запрос не вернул данные. Нулевые показатели после первого подключения не доказывают отсутствие аудитории или активности: синхронизация могла ещё не завершиться. На первой проверке 2026-11-19 подключение было подтверждено, но список постов оказался пустым, а сводные показатели — нулевыми. Это исторический результат, не текущая статистика. При необходимости объясни ограничение и повтори запрос позже, без бесконечных повторов.

Не обещай доступ ко всей ленте Threads, произвольным чужим постам, личным сообщениям или текстам комментариев. Возможности чтения и поиска за пределами собственного аккаунта проверяй отдельно по текущим инструментам, разрешениям и документации. Аналитику счётчика ответов нельзя выдавать за чтение обсуждений.

## Подготовка и планирование публикаций

- Различай просьбу написать черновик и поручение опубликовать/запланировать. Подключение аккаунта само по себе не разрешает публиковать тестовые сообщения.
- Подготовь текст и необходимые медиа. Для выполнения нужны однозначный аккаунт, содержание и время с часовым поясом. Если пользователь уже разрешил конкретную публикацию и всё определено, выполняй без повторного согласования. Запрашивай только действительно недостающие данные.
- Перед планированием читай текущую схему `createScheduledPost`. В известной версии она принимает `blogId`, `date`, `info` и опционально `mediaFiles`. `info` — строка JSON со структурой публикации, а не произвольный текст. Получи её точный формат из текущего описания инструмента или официальной документации; не угадывай ключи и значения провайдера.
- Для проверки очереди используй `getScheduledPosts`, указав бренд, период и часовой пояс из настроек. Этот инструмент возвращает только ещё не опубликованные посты, а не историю публикаций.
- Не вызывай `getBestTimeToPostByNetwork` для Threads, если в текущей схеме эта сеть отсутствует. В проверенной версии принимались только Twitter, Facebook, Instagram, LinkedIn, YouTube и TikTok. При отсутствии данных о лучшем времени используй время, заданное пользователем, либо уточни его.
- Для правки сначала получи исходный пост через `getScheduledPosts`. В `updateScheduledPost` сохраняй полное содержимое и меняй только запрошенные поля. После обновления ID может измениться, UUID сохраняется; используй новые идентификаторы из ответа.
- Если результат записи неизвестен из-за тайм-аута, сначала проверь очередь, чтобы не создать дубликат. Окончательную ошибку инструмента не повторяй с теми же аргументами.
- После успешного действия сообщи точное время, часовой пояс и вернувшуюся ссылку `plannerUrl`, если она есть. Различай «запланировано» и «опубликовано»: помещение в очередь не подтверждает выход поста в Threads.
- Поток согласования с рецензентами используй только по соответствующей задаче. Это отдельная функция с тарифными ограничениями и возможной отправкой email; обычное планирование её не требует.

## Автоматизация и тариф

Плагин даёт инструменты чтения и записи, но не создаёт расписание работы самого агента. Разовая запланированная публикация в Metricool отличается от повторяющейся задачи агента, например еженедельного отчёта. Создавай такую автоматизацию только по задаче пользователя и проверяй доступ к плагину в среде её выполнения.

На момент настройки документация Metricool указывала доступ к MCP на Free, до 20 запланированных публикаций в месяц и 30 дней аналитики. Это не отдельная квота для Threads. Перед обещанием бесплатного объёма или выбором платного тарифа перепроверь условия. Ничего не покупай только ради подключения.
